# Bug Report Template

Standard format for reporting defects found during manual or automated testing of the signal management application.

A good bug report lets the developer reproduce the issue **without asking a single follow-up question**. If they have to come back and ask for more details, the report is incomplete.

---

## Template

Copy the block below into your issue tracker (Jira, Redmine, GitHub Issues, etc.) and fill in each field.
Title:
[Short, specific summary — what is broken, where, and under what conditions]

Environment:

Application version / build: [e.g. 1.4.2 (build 2025-09-27)]

OS: [e.g. Windows 11 23H2]

Service simulator version: [e.g. 1.0]

Network conditions: [e.g. localhost, no throttling]

Preconditions:

[What must be true before the steps below — e.g. "Service simulator running on port 2001", "User logged in", "Table already populated"]

Steps to reproduce:

[First action — be specific]

[Second action]

[Third action]

[Continue until the bug is reached]

Expected result:
[What should happen]

Actual result:
[What actually happens]

Severity: [Critical / Major / Minor / Trivial]
Priority: [High / Medium / Low]

Attachments:

□ Screenshot
□ Video / screen recording
□ Application logs
□ Service logs
□ Network capture (if relevant)
Additional notes:
[Anything else useful — reproducibility rate, related issues, workarounds]
